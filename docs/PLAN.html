Agent Company — 一个可生长的 AI 公司

你(老板)发出一个想法,系统自动组建团队、分配任务、协作执行、测试验收,最终交付成品。部门、岗位、agent 都可以由你随时增减,公司随项目一起长出来。

00

一句话定位

把"一个公司如何运转"翻译成可执行的多 agent 编排系统。

核心隐喻

workspace 是一家公司,文件夹里的人是各部门 agent。老板说一句话 = 启动一个项目,部门主管接单、拆解、派活,一线 agent 干活产出,QA 把关,运营交付。所有产物落地成真实文件,人(你)随时可以下场检查、调整、加人。

关键规则

QA 阶段是"质量闸口":测试不通过自动打回研发部对应组(标失败原因),研发修复后重新进 QA。研发和设计可以并行(都依赖 PRD)。老板可以随时介入任意阶段。

核心数据模型

4 个核心结构撑起整个系统。YAML 配置 + SQLite 存储。

① 公司组织 (company.yaml)

company:
  name: "球球的 AI 公司"
  boss: "球球"

departments:
  - id: dev
    name: "研发部"
    head: dev-head          # agent id
    teams: [frontend, backend]
  - id: qa
    name: "质量部"
    head: qa-head

agents:
  - id: dev-head
    department: dev
    role: head              # head | leader | worker
    llm: claude-sonnet      # 引用 LLM provider
    system_prompt: |
      你是研发主管,负责拆解需求、分配任务...
    tools: [bash, edit, glob, grep]
  - id: frontend-worker-1
    department: dev
    team: frontend
    role: worker
    llm: gpt-4o
    tools: [bash, edit, web_fetch]

llm_providers:
  - id: claude-sonnet
    type: anthropic
    api_key: sk-ant-...
    model: claude-sonnet-4-5
  - id: gpt-4o
    type: openai
    endpoint: https://api.openai.com/v1   # 可指向第三方
    api_key: sk-...
    model: gpt-4o

② LLM Provider(关键)

// 多 provider 抽象,支持任意
// 兼容 Anthropic / OpenAI 协议的 endpoint

interface LLMProvider {
  id: string
  type: 'anthropic' | 'openai'
  endpoint?: string    // 留空 = 官方
  apiKey: string
  model: string
  maxTokens?: number
  temperature?: number
}

class LLMRegistry {
  add(p: LLMProvider)
  chat(id, msgs): AsyncIterable
  list(): LLMProvider[]
}

第三方接入示例:填入 https://api.deepseek.com/v1 + DeepSeek key,选 type: openai,就能用 DeepSeek 当 agent 大脑。

③ 项目 (Project)

interface Project {
  id: string             // proj-20260813-001
  title: string
  boss: string           // 球球
  status: 'idea' | 'prd'
        | 'design' | 'dev' | 'qa'
        | 'delivery' | 'done'
  createdAt: number
  phases: Phase[]        // 6 个阶段
  deliverables: {
    prd?: string         // 文件路径
    design?: string[]
    src?: string
    testReport?: string
  }
}

interface Phase {
  id: string             // 'prd' | 'design' | ...
  status: 'pending' | 'running'
        | 'done' | 'failed' | 'blocked'
  tasks: Task[]
  startedAt?: number
  finishedAt?: number
}

④ 任务 (Task)

interface Task {
  id: string             // task-001
  projectId: string
  phase: string          // 所属阶段
  department: string
  assignee: string       // agent id
  status: 'pending' | 'running'
        | 'done' | 'failed' | 'blocked'
  input: {
    prompt: string       // 任务指令
    files?: string[]     // 输入文件
  }
  output?: {
    files?: string[]     // 产出文件
    summary: string      // 摘要
  }
  dependsOn: string[]    // 前置任务
  attempts: number       // 重试次数
  cost?: {               // 资源消耗
    tokens: number
    duration: number
  }
}
05

运行时核心 · 4 个关键模块

从"定义"到"跑起来"需要这四块。

LLM 抽象层 (server/runtime/llm)
统一 Anthropic / OpenAI 协议,实现流式 chat + tool use。配置存 SQLite,运行时按 agent 的 llm 字段路由。
Agent Runtime
每个 agent 跑在独立 Node.js 子进程 / Worker 中,加载 system_prompt + tools + 历史,执行任务,输出结构化结果。
Orchestrator 调度器
监听项目状态机,推进 phase 流转,处理 agent 完成/失败事件,触发下一阶段。可视作"PMO 办公室"。
WebSocket 事件总线
实时推送 agent 输出、日志、状态变化给前端 Dashboard。老板可"围观"全过程。

实施路径 · 3 阶段交付

完整公司形态 = 3 周。每个阶段都跑得通,前一阶段是后一阶段的地基。

PHASE 1

地基 · 跑通单部门闭环

5 天
能让一个 agent 跑起来 + 接收任务 + 输出产物 + 老板能看到。
  • LLM 抽象层(Anthropic + OpenAI 协议,可加第三方 endpoint)
  • Agent Runtime 最小实现(system_prompt + tools + chat loop)
  • SQLite 存项目/任务/产物
  • Web Dashboard v1(只读,看公司状态 + 单项目进度)
  • YAML 配置 + 热重载
  • CLI 启动脚本 ac start
  • 🎯 验收: 能跑通"老板说一句话 → 一个 dev agent 写代码 → 产出文件"
PHASE 2

骨架 · 多部门流水线

7 天
6 个部门全配上,Orchestrator 调度,完整流水线跑通。
  • Orchestrator 实现: 6 phase 状态机,依赖图调度
  • 所有部门模板(产品/设计/研发/QA/运营/HR) + 默认 agent 配置
  • Head / Leader / Worker 三级角色协作
  • Web Dashboard v2: Kanban + 部门管理 + 实时日志
  • 对话式配置(在 Mavis 里用 mavis 工具改 YAML)
  • 任务失败重试 + QA 打回机制
  • 🎯 验收: "做个健康科普网页" 全自动跑完 → 网页 + 测试报告交付
PHASE 3

血肉 · 完整公司形态

5 天
高级特性 + 多模态 + 知识沉淀 + 自我演进。
  • 多模态部门: 视频/音乐/插画 agent(对接 gen_videos / batch_text_to_music)
  • 跨项目知识库: agent 完成项目后把经验写进共享 memory
  • agent 自我反思: 任务失败后 agent 自己分析 + 改 prompt
  • Web Dashboard v3: 仪表盘统计、token 消耗、agent 性能排行
  • 多 boss / 多项目并行
  • 🎯 验收: 老板发"做个完整产品+营销视频",公司独立完成从 PRD 到宣传片全链路

还需要你拍板的 4 个开放问题

这些不阻塞 Phase 1,但 Phase 2 之前要确定。

❶ Agent 跑代码沙箱?

写代码的 agent 要不要在隔离环境里跑?这关系到本机安全和并发能力。

方案 A 直接本机跑(快,信任 agent)
方案 B Docker 容器隔离(安全,慢)
方案 C 后期再加,先本机

❷ Agent 怎么"看"别人的产物?

设计部产出设计稿,前端 agent 怎么拿到?这决定数据流设计。

方案 A 文件路径(简单,文件即接口)
方案 B 中间产物存对象存储
方案 C 全部塞进 prompt 上下文

❸ 任务失败怎么办?

agent 跑挂了/产出不合格的兜底策略。

方案 A 自动重试 N 次(简单)
方案 B 重试 + 升级到 Leader agent 接手
方案 C 打回老板决策

❹ 项目并发上限?

同时跑多少个项目 + agent。决定 token 消耗和调度策略。

方案 A 同时只跑 1 个(稳)
方案 B 最多 3 个项目并行
方案 C 不限,按资源弹性
当前推荐

沙箱用 C(后期再加)、产物用 A(文件路径)、失败用 B(重试 + 升级)、并发用 B(3 并行)。这些可以在 Phase 1 跑起来后再调,先开工。
